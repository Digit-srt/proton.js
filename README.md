# Proton.js

Proton.js is a Rust application framework that renders HTML, CSS, and JavaScript with Servo. It includes a single-window desktop runtime and Proton Batcher, the standalone `pb` command-line tool.

## Quick start

1. Open the [v0.2.0 preview release](https://github.com/Digit-srt/proton.js/releases/tag/v0.2.0) and extract the Windows x64 ZIP.
2. Launch `Proton.exe` to see the welcome screen, or extract the separate Three.js demo ZIP and launch its `Proton.exe`.
3. Add the directory containing `pb.exe` to your PATH. From a terminal, create and build a project.

```sh
pb init hello
cd hello
pb -build -win
```

Open `dist/win/Proton.exe`. Edit `web/index.html` and keep your CSS, JavaScript, images, and other static files under `web/`. Keep that directory beside the executable when moving a packaged app.

## Build targets

| Command | Output | Build environment |
| --- | --- | --- |
| `pb -build -win` | `dist/win/Proton.exe` | Windows x64, Rust 1.100+, Git, MSVC C++ tools, Windows SDK, LLVM, and CMake |
| `pb -build -linux` | `dist/linux/proton` | Linux x64 or ARM64, Rust 1.100+, Git, and Servo's native build dependencies |
| `pb -build -android` | `dist/android/Proton-debug.apk` | JDK 17+, Gradle 9.8.2, Android SDK Platform 37.0, and Build Tools 36.0.0 |

On Windows, build from an x64 Native Tools terminal. If Clang is in a custom location, set `LIBCLANG_PATH` to LLVM's `bin` directory. To build for Linux from Windows, use the Linux version of `pb` in a WSL distribution. [Windows build requirements](https://book.servo.org/building/windows.html) · [Linux build requirements](https://book.servo.org/building/linux.html)

For Android builds, set `ANDROID_HOME` and put Gradle on your PATH. Use `PROTON_GRADLE` for a custom Gradle executable. On the first build, `pb` downloads the official Servo AAR with `curl` and verifies its SHA-256 digest. To supply a cached copy, set `PROTON_SERVO_AAR`. The debug APK targets ARM64 devices running Android 10 or newer. [Servo 0.8.0 Android library](https://github.com/servo/servo/releases/tag/v0.8.0)

## Build from source

```sh
cargo install --path . --locked
pb --version
pb -build -win --welcome
```

Run the last command on Windows from the repository root. The `--welcome` option packages the built-in getting-started screen on any supported build target. The first desktop build compiles Servo. Later builds reuse the `.proton/` cache. Set `CARGO_TARGET_DIR` to a shared absolute directory to reuse desktop build artifacts across projects.

## Graphics and examples

The desktop runtime enables WebGL 1, WebGL 2, and WebGPU. Servo serves the packaged assets at `https://app.proton.invalid` inside the runtime. Select **Run graphics tests** in the project generated by `pb init` to read back WebGL pixels and verify a WGSL computation.

The offline [Three.js example](examples/threejs) draws a rotating 3D knot and verifies the first frame using WebGL 2 readback. To build it from source on Windows, run `pb -build -win` from `examples/threejs` and open `dist/win/Proton.exe`.

After editing the example's `scene.js`, regenerate the bundled script from the example directory.

```sh
esbuild scene.js --bundle --format=iife --target=es2022 --minify --charset=utf8 --legal-comments=inline --outfile=web/scene.bundle.js
```

WebGL 1, WebGL 2, WebGPU compute, and the Three.js scene were verified on Windows x64. Linux graphics remain unverified. The Android APK was built and its signature was checked. Servo 0.8.0 cannot open a WebGPU adapter from the Android package's default `file://` entry page. [Servo experimental graphics features](https://book.servo.org/design-documentation/experimental-features.html)
